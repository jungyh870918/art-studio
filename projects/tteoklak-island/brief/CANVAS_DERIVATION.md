# CANVAS DERIVATION — D1이 정해지면 규격이 어떻게 되는가

작성 2026-08-17 · 스튜디오
근거 측정: [`MOCKUP_UI_AUDIT.md`](MOCKUP_UI_AUDIT.md) · 대상 결정: `REQUEST_TO_DIRECTOR.md` §D1

`REQUEST` §D1은 **「기준 캔버스를 정해 달라」**고만 한다.
그런데 값을 고르려면 **그 값이 정해졌을 때 무엇이 어떻게 되는지**가 먼저 보여야 한다.
이 문서가 그 표다. **디렉터가 숫자를 보고 고를 수 있게 하는 것이 목적이다.**

---

## 1. D1이 지배하는 범위 — 기획서 §05가 이미 정해 놨다

> **2026-08-17 정정.** 이 절은 처음에 「D1은 사실 질문이 둘이다」로 썼다.
> 그 뒤 기획서 §05 원문을 읽었고, **답이 이미 문서에 있었다.** 아래가 정정판이다.

기획서 §05는 화면을 **세 층**으로 가르고, 층마다 해상도를 다르게 규정한다.

| 층 | 해상도 | 무엇이 여기 있는가 | D1에 걸리나 |
|---|---|---|---|
| **World** | **기준 캔버스** (미확정 = D1) | 배경 · 캐릭터 · 소품 · 이펙트 · 자막 | **걸린다** |
| **Interaction** | **기기 실제 해상도** | 상단 바 · 상황 라인 · 행동 메뉴 · 선택지 카드 · 가방 · 배틀 HUD | 안 걸린다 |
| **Meta** | **기기 실제 해상도** | 수첩 · 대화 기록 · 저장 · 설정 · 타이틀 | 안 걸린다 |

§05 머리에 경고가 붙어 있다 — **「이 장의 전제가 §23으로 뒤집혔다. 세 층 구조는 그대로 유효하지만,
월드 쪽 숫자는 기준 캔버스가 정해질 때까지 미확정이다.」**
즉 **D1은 World 층 숫자를 채우는 결정**이고, 그 이상이 아니다.

### 그래서 무엇이 달라지나

- **D1이 지배하는 것은 배경과 캐릭터뿐이다.** UI 아이콘·장식은 애초에 D1 종속이 아니다
- **초상화도 D1에 안 걸린다.** 대화 UI이므로 Interaction 층이다.
  §05가 「초상화 96×96이 세계 화면의 절반 이상을 덮는다」를 구 방식의 문제로 들며 UI로 올렸다
- **`REQUEST` §5의 「D1만 정해지면 초상화를 발주할 수 있다」는 한 단계 더 낫다 —
  초상화는 D1을 기다릴 필요조차 없다**

**아래 표는 아트 제작 캔버스 기준이다.** World 층 자산(배경·캐릭터)에는 확정 규격이고,
UI 층 자산에는 **「목업 좌표계에서 이 크기로 보인다」는 기준값**이다 —
실제 표시는 기기 해상도에 맞춰 정수 배율로 확대된다.

## 2. 후보 세 안

| | 캔버스 | 목업 대비 | 성격 |
|---|---|---|---|
| **가** | **941×1672** | ×1.000 | 목업 그대로. 앵커와 자산이 같은 좌표계 |
| **나** | **1080×1920** | ×1.148 | 9:16 표준. `REQUEST`가 든 안 |
| **다** | **1440×2560** | ×1.530 | 여유분. 고배율 기기 + 후일 축소 |

세로 비율이 셋 다 정확히 9:16이 아니다 — 목업은 941:1672 = **0.5629** (9:16 = 0.5625).
오차 0.07%이므로 실사용에 문제 없다.

### 안별 장단

**가 (941×1672)**
- 앵커와 생성물이 **같은 크기**다. 대조 시트에서 1:1로 겹쳐 볼 수 있다
- 목업의 UI 부품을 **그대로 잘라 임시 자산으로 쓸 수 있다** — 셸 구현이 빨라진다
- 다만 941은 표준값이 아니라, 나중에 1080으로 옮길 때 한 번 더 리사이즈가 생긴다

**나 (1080×1920)**
- 흔한 값이라 기기 대응이 깔끔하다
- **×1.148은 정수배가 아니다.** 목업을 앵커로 쓸 때 매번 리샘플이 끼고,
  [`ART_DIRECTION`](ART_DIRECTION.md) §2가 확인한 「업스케일 배수 1×, 픽셀 격자 없음」과 어긋날 여지가 있다
- 회화체 자산에는 사실상 무해하지만, **도트체인 P4 수첩 흉상에는 눈에 띈다**

**다 (1440×2560)**
- 축소는 안전하고 확대는 위험하다는 원칙에 가장 맞다
- 생성 비용·용량이 가장 크고, 지금 왕복 100회 문제(§`QUESTIONS_TO_STUDIO` §1)를 더 키운다

## 4. D1의 영향을 받지 않는 것

전부 기다릴 필요는 없다. 아래는 지금 진행해도 된다.

| 자산 | 왜 안 기다려도 되나 |
|---|---|
| **배경** | 크게 받아 줄인다. `REQUEST` §D1도 같은 판단 ✅ |
| **아이템 아이콘 12개** | 다른 이유로 막혀 있다 — **목업에 인벤토리 화면이 없다.** 셸 설계가 먼저 |
| **타이틀** | 목업에 없다. 화면 설계가 먼저 |

**아이템 아이콘은 D1으로 풀리지 않는다.** `REQUEST` §2-4가 「D1 이후 재산출」이라고 적었는데,
목업 어디에도 가방 시트 화면이 없어서 **잴 대상이 없다.**
증거 썸네일(188×168)과 같은 것인지 별개인지도 미확인이다
([`MOCKUP_UI_AUDIT`](MOCKUP_UI_AUDIT.md) §4).

## 5. 결정 — 「가 (941×1672)」

디렉터가 스튜디오 판단대로 진행하라고 지시했다.
**잠정 결정과 근거·번복 비용은 [`../STUDIO_DECISIONS.md`](../STUDIO_DECISIONS.md) §2에 있다.**

요지만 적으면:

- **앵커와 생성물의 좌표계가 같아진다.** 대조 시트에서 1:1로 겹쳐 본다
- **목업에서 UI 부품을 잘라 임시 자산으로 쓸 수 있다.** 셸 구현이 빨라진다
- **승인 자산이 0개다.** 옮기는 비용이 지금 가장 싸다
- **1080×1920은 ×1.148로 정수배가 아니다.** 정수배로 갈 거라면 **941 → 1882(×2)**가 더 안전하다
- **1440×2560은 지금 권하지 않는다.** 생성 왕복이 이미 병목이다
  ([`QUESTIONS_TO_STUDIO`](../QUESTIONS_TO_STUDIO.md) §1)

> **§3 표의 「가」 열이 확정판이다.** 발주서에 그대로 붙인다.
> 되돌려야 한다면 **배경 6장이 승인되기 전**에 해야 한다.

### 초상화는 지금 발주할 수 있는가

§1대로 초상화는 D1에 걸리지 않으므로 **캔버스 때문에 막히지는 않는다.**
다만 두 가지가 남아 있다.

1. **표정 목록** — 대사 데이터에 표정 필드가 **없어서 추출이 불가능하다.** 설계해야 한다
2. **윤세라 외형** — 목업과 `data/characters` 가 서로 다르다
   ([`../STUDIO_DECISIONS.md`](../STUDIO_DECISIONS.md) §6)

**나머지 4명은 지금 발주 가능하다.**
