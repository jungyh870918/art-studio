## 2. 표기 규칙

<!--
프로젝트마다 다시 정하지 않는다. 아래 규칙을 그대로 쓴다.
새 상태 이름이나 별도의 진행 체계를 덧붙이지 않는다.
-->

**상태** — `06_ASSET_LIFECYCLE.md`의 상태를 그대로 쓴다.

```text
REFERENCE · CONCEPT · CANDIDATE · APPROVED
보조: REJECTED · ON HOLD · SUPERSEDED
```

- 아직 아무 결과물도 없는 자산은 `—`로 둔다.
  이것은 새 상태가 아니라 **상태가 아직 없다**는 표시다. 필요하지만 시작하지 않은 자산이다.
- `EXPORT`는 Approved source에서 파생된 결과이므로 상태 칸이 아니라 Export 칸에서 본다.
  상태 칸은 그 자산의 **현재 공식 source가 어디까지 왔는지**를 가리킨다.
- 승인 범위가 갈릴 때는 상태에 `APPROVED`를 쓰고 남은 부분을 메모에 한 줄로 남긴다.
  (예: 실루엣 승인 / 색 미확정)

**Approved Source** — 디렉터가 채택한 공식 원본의 위치. 승인 전에는 비운다.
여러 파일로 구성된 자산이면 폴더 경로를 적는다.
`approved/`에 파일이 있다는 사실이 승인을 만들지 않는다. 이 칸은 디렉터의 결정 결과를 가리킬 뿐이다.

**Export** — Approved source에서 파생된 엔진·플랫폼용 결과.

```text
없음 / <target> 있음 / <target> 없음 / <target> stale
```

Export는 source를 대체하지 않는다. Export만 있고 Approved Source가 비어 있는 행은 잘못된 상태다.

**검증** — 기술 검사와 runtime 확인의 현재 상황. 짧은 자연어로 적는다.

```text
미확인 / 기술 검사 통과 / runtime 확인 완료
runtime 문제 — export 원인 / runtime 문제 — source 수정 필요
```

> **이 칸의 내용은 상태 칸을 바꾸지 않는다.**
> 기술 검사 통과는 승인이 아니다. 상태를 `APPROVED`로 바꿀 수 있는 것은 디렉터의 채택뿐이다.

**이름** — 프로젝트 안에서 안정적으로 참조할 수 있는, 사람이 읽을 수 있는 이름.
프로젝트에 naming rule이 있으면 그것을 따른다. 여기서 새 ID 체계를 만들지 않는다.
이미 쓰는 asset ID가 있다면 이름 옆에 함께 적어도 된다.

**메모 · 참조** — 한 줄. 관련 `ASSET_BRIEF` / `REVIEW_LOG` 위치, 승인 범위, 파생 관계, 세트 구성 수 등.
길어지면 그 문서로 보낸다.
