## 1. 정정 접수 — 「겹침 0」은 도달 불가. 제 값이 또 틀렸다

**소패·광릉의 `ny` 가 정확히 같고(0.462) 가로 간격이 64.9px.** 재현했다.
세로 거리가 0 이니 늘리기로는 영원히 안 벌어진다. 그 쌍을 빼면 장안·동관까지
**22,100px** — 화면 1672 기준 13배, 콘텐츠 1421 기준 16배. 그쪽 값과 맞다.

**제 60,100px 은 스크립트의 반복 상한을 답으로 읽은 것이다.
같은 실수를 두 번 했다** — 앞서 40,000 도 같은 원인이었다.
`marker_density.js` 에 세로 거리 0 인 쌍을 먼저 걸러내는 검사를 넣고 상한도 분리했다.

**결론은 그쪽 말대로 오히려 세진다** — 늘리기로는 원리적으로 0 이 안 되므로
「한꺼번에 보여주지 않는 규칙」은 **선택이 아니라 필수**다.

그 밖에 받은 정정도 반영했다.

- **劉는 여섯** (유선 누락). 동시 최대 5 는 그대로. `IDENTIFICATION_SYSTEM.md` 고쳤다
- **60px 칸 52 vs 53** — 동점 처리 차이로 본다. 결론에 영향 없어 그대로 둔다
- 검사기 인자화 · 한자 표 내장 확인했다. **한자 표가 검사기의 것이지 게임 데이터가
  아니라는 단서**가 중요하다 — 나중에 배너를 만들 때 그 표가 유일한 출처가 된다.
  A안으로 가면 **그 표가 게임 데이터로 승격되어야 한다**

## 2. 좌표판 판정

| | 판정 |
|---|---|
| **D1** (0.59 · 전부 얼굴) | 무너진다. 이견 없다. **다만 마커가 UI 패널 위로 올라탄다** — 층 규칙에 「마커는 패널 아래」를 추가했다 |
| **D2** (1.51 · 전부 얼굴) | **수치는 3분의 1인데 화면은 그만큼 안 나아진다.** 중원 밀집이 가로세로 양쪽이라 세로 확장 효과가 절반만 오고, 대신 왼쪽 아래가 비어 **화면 3분의 1이 죽고 남북이 과장된다** |
| **D3** (얼굴 38 + 점 29) | **유일하게 읽힌다. 이 방향으로 간다** |
| **D4** (점만) | **전부 읽힌다.** 「하한선」이라 부르기엔 과소평가다 — 지도가 해야 할 일을 이미 다 한다 |

**종횡비 후보를 1.1~1.3 으로 좁혔다.** 1.51 은 얻는 것에 비해 죽은 공간과 왜곡이 크다.
1.1~1.3 이면 겹침은 절반(87쌍)으로 줄면서 그 둘이 훨씬 적다.

**솎는 규칙은 뒤집혀 있다.** 「큰 도시 우선 그리디」는 결과적으로 **고립된 곳을 우대한다** —
자리가 겹치면 버리므로 변방이 살아남는다.

```
얼굴을 받은 곳   운남 · 교지 · 건녕 · 낙랑 · 영안   (변방 · 규모 1급)
점으로 밀린 곳   진류 · 소패 · 수춘 · 완 · 여강     (중원 · 190년의 격전지)
```

190년에 **진류와 수춘이 점이고 교지가 얼굴인 화면**은 게임의 무게중심과 반대다.
그쪽이 단 단서가 정확하다. **기준은 「자리가 남는가」가 아니라 「지금 중요한가」여야 한다.**
관문 18이 점으로 밀린 것은 타당하다 — 그것은 **Q11 의 답에 가깝다.**

## 3. 네 장이 드러낸 더 큰 문제 — 이쪽이 본론이다

D2 에서 **겹치지 않는 자리의 얼굴들도 서로 구별되지 않는다.**
어두운 갑옷 · 어두운 배경 · 비슷한 밝기가 반복되어 **얼굴 무늬로 읽힌다.**

측정했다. 승인 원화 22장을 규약 §2 의 크롭 방식대로 78px 흉상으로 줄이고 장끼리 평균색 거리:

```
평균 밝기 L*     13.3 / 100        밝기 표준편차 5.2
장끼리 ΔE        중앙값 5.5 · 25%분위 3.6
ΔE < 10 인 쌍    231 중 204  (88%)

비교 — 같은 자로 잰 세력색 20종은 ΔE 중앙값 60 이상, ΔE<30 이 7쌍뿐
```

> **색 덩어리로 보면 초상 22장은 서로 거의 같은 물건이다.**

**이것은 초상이 잘못됐다는 뜻이 아니다.** 규약 §3 이 「전체가 어두운 저조 그림」을
명시적으로 요구했고 그대로 지켜졌다. 한 장을 볼 때는 그것이 옳다.

**Q7 과 모순되지 않는다. 층이 다르다.**

| | 판정 | 근거 |
|---|---|---|
| 흉상 **한 장**이 78px 에서 그 인물로 읽히는가 | **읽힌다** | 그쪽 Q7 시트. 홍안·안대·면류관·유건이 남는다 |
| 흉상 **67장**이 한 화면에서 서로 갈리는가 | **안 갈린다** | 위 측정 |

개별 식별과 **집합 속 변별**은 다른 문제다. Q7 은 전자를 증명했고 D2 는 후자를 반증한다.

**그래서 지금 화면에서 세력을 갈라 주는 것은 얼굴이 아니라 프레임 테두리 색이다.**
얼굴은 자리를 차지하면서 그 일을 돕지 못하고 있다.

### 따라오는 것 둘

**① 다섯 번째 선택지를 올린다 — ㉲ 지도에서 얼굴을 내린다**

상시 표시는 점 마커, **도시를 «고르면»** 그때 반신 초상이 크게 뜬다.

- D4 의 가독성 + 초상의 존재감을 둘 다 얻는다.
  78px 로 67개 깔아 무늬로 만드는 것보다 **610px 로 한 장 보여주는 쪽이 강하다**
- **Q11(관문 21곳)이 자동으로 사라진다** — 관문은 원래 얼굴이 없다
- **목업의 인상에서 멀어진다. 이것이 유일한 손실이고 작지 않다**

**Studio 는 이 안을 권고하지 않는다. 선택지로만 올린다.**
목업의 「지도에 얼굴이 깔린 화면」은 디렉터가 정한 도달 목표이고,
그것을 포기할지는 아트가 아니라 디렉터의 결정이다.

**② 얼굴을 지도에 남긴다면 — 마커 전용 흉상 파생 처리가 필요하다**

승인 원화는 **그대로 두고**, 마커용 파생본에만 밝기를 올리고 계조를 줄이고
색조를 세력 쪽으로 민다. `03` §16 의 원본→파생 방향이고
**초상 규약을 고치지 않는다** — 규약은 원본의 규칙이다.
효과는 위와 같은 자로 검증 가능하다(파생본끼리 ΔE 중앙값이 얼마나 오르는가).

## 4. 원화 보관 — git-lfs 선행 조건 접수

**`brew install git-lfs` 가 먼저**라는 것, 그리고 전역 gitconfig 에 `filter.lfs.*` 만
남아 있어 그대로 `.gitattributes` 를 걸면 커밋이 깨진다는 것 — 접수했다.
**`assets/` 가 한 번도 커밋된 적이 없어 히스토리 재작성이 0 이라는 것이 결정적이다.**
지금이 가장 싼 시점이라는 판단에 동의한다.

`manifests/` 를 일반 git 에 남기는 조건에 합의된 것으로 본다.

**순서만 덧붙인다** — `brew install git-lfs` → `git lfs install` →
`.gitattributes` → **그다음에 첫 커밋.** 순서가 바뀌면 포인터가 아니라 실파일이 들어간다.

## 5. 색 수정 — 원인 진단이 제 것보다 정확하다

`st.clans` 가 망한 세력을 **지우지 않고 `alive:false` 로 남긴다**는 것 —
저는 `nid % 20` 만 보고 「20을 넘으면」이라고 적었는데, 실제로는
**20세력 시나리오에서 첫 반란이 바로 0번 색을 받는다.** 훨씬 이른 시점이다.
`Events.clanColor(st)` 로 살아 있는 세력 기준으로 고른 것이 맞는 해법이다.

팔레트 재설계(ΔE 7쌍)가 Q1 뒤라는 데 동의한다.
**다만 §3 의 측정이 하나를 바꾼다** — 얼굴이 서로 안 갈리는 이상
**테두리 색의 부담이 예상보다 크다.** 팔레트 재설계의 우선순위가 올라간다.
