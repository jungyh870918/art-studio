## 3. 핵심 게임 경험

- **지도를 오래 본다.** 46개 도시가 얹힌 중국 전역이 기본 화면이고, 플레이어는
  여기서 대부분의 시간을 보낸다
- **인물의 얼굴을 자주, 가까이 본다.** 무장 181명이 등용·임명·전투·사서 이벤트에
  계속 등장한다. 초상이 이 게임의 정서를 거의 혼자 지고 있다
- **수치를 읽는다.** 금·군량·병력·민심·개발·치안, 그리고 무장 6능력치.
  화면 대부분이 숫자와 그 숫자를 읽히게 만드는 장치다
- **전투는 격자 위에서 벌어진다.** 현재 16×9 격자에 부대가 놓이고 턴제로 움직인다
- 한 판이 길다. 같은 화면을 수백 번 다시 본다 — **반복 노출을 견디는 그림**이 필요하다

**장르:** 턴제 역사 시뮬레이션 / 전략

```text

[ 도시 명령 ] 개발·군사·인사·외교·계략·상인·정보·특별

[ 전투 격자 ] 턴제 → 승패        │
      ↓                          │
   계절 진행 (봄·여름·가을·겨울) ─┘
      ↓
사서 이벤트 138종이 흐름에 끼어든다
      ↓
천하 통일 → 엔딩
```

## 6. 카메라와 화면

- 카메라 유형: 2D 고정. 화면마다 다르다 —
  지도는 **부감(비스듬히 내려다봄)**, 전투는 **정사각 top-down**, 무장은 정면 초상
  (근거: `../reviews/2026-08-17_mockup-spec-recovery/FINDINGS.md` §2-3 · §2-5)
- 일반적인 카메라 거리: 지도 = 중국 전역이 한 화면. 전투 = 격자 8~9칸이 한 화면
- 화면 속 주요 오브젝트의 대략적 크기 (목업 941px 폭 기준):
  - 성채 217~268 × 110~160
  - 인물 마커 **78 × 80 확정** (Q7 닫힘 — 초상 22장을 두 크기로 렌더해 확인. 회화 흉상은 60에서도 견딘다)
  - 전투 격자 셀 ~107 × 102
  - 무장 상세 초상 ~610 × 600
- 줌 또는 시점 변화: **없다** (게임 쪽 확인). 640×378 고정 · CSS 2배. **이것이 마커 밀도 문제의 원인이다**
- 기본 화면 비율: **9:16** (941×1672 는 9:16 에서 0.5px 안에 든다)
- 목표 기준 해상도: **미정 — 이 발주의 핵심 결정 항목.** STYLE_SPEC §3 에 후보 3안
- 대응이 필요한 다른 화면: 데스크톱 1280×800 가로 (유지 여부 → REQUEST Q5)

## 7. 세계와 배경

**세계 설명:** 한 왕조가 무너지고 군웅이 각축하는 중국. 사서에 남은 실제 인물과
사건을 따르되, 연의의 극적 각색도 함께 쓴다

**시대:** 후한 말 ~ 삼국 (2~3세기)

**장소·지역:** 13주 · 46 도시. 북방 평원 · 장강 · 촉의 산 · 서량 황토 · 남방 밀림까지
기후와 지형이 크게 갈린다 (세력별 배경 17종이 `docs/portrait-style-guide.md` §5 에 이미 정의됨)

**고증이나 문화적 맥락이 중요한가:** **중요하다.**
2세기 한나라 복식(찰갑·천만), 한자 배너, 중국 건축. 서양 판타지 갑옷은 명시적 금지.
다만 이 게임의 고증은 **박물관 수준이 아니라 「1990년대 일본 역사 게임이 이해한
후한 말」**이다 — 두 겹 구조는 ART_DIRECTION §1 에 있다

## 11. 플레이 가독성 요구

**화면에서 반드시 읽혀야 하는 정보:**

- **소속 세력** — 지도에 여러 세력의 도시·인물이 동시에 놓인다. 즉시 갈려야 한다
- **누구인가** — 마커 ~78×80 에서도 그 무장으로 보여야 한다 (초상 규약 §7 이 이미 대응)
- **도시의 규모와 주인** — 성채 형태(규모)와 색·깃발(소속)
- **전투에서 이동 가능 / 공격 가능 칸** — 초록 / 빨강 오버레이
- **수치** — 금·군량·병력·민심 등이 배경 위에서 읽혀야 한다.
  지도 위에 흰 글자가 직접 얹히는 자리가 있다
- **부대의 병종과 병력** — 전투 격자에서 스프라이트만으로 병종이 갈려야 한다

**게임 화면에서 발생하면 안 되는 문제:**

- 세력색만으로 구분하게 만들면 안 된다 (색각 · 순간 판단 · 세력 20개 규모)
- 지도 위 글자가 지형에 먹히면 안 된다
- 인물 마커가 축소에서 얼룩이 되면 안 된다
- 타일 반복이 드러나면 안 된다 (지도를 타일로 갈 경우)
- **반쪽 픽셀이 생기면 안 된다** — 정수 배율이 깨지면 도트가 뭉갠다

## 13. 기술적 제약

- **빌드 없음 · 의존성 없음 · 정적 파일.** 번들러가 없다.
  자산은 파일이거나 소스에 박힌 data URL 이다
- **현재 초상이 data URL 로 박혀 있다** — `js/art.js` 가 22장에 244KB.
  181장이면 같은 방식으로는 못 간다 (약 2MB, 파싱 비용도 붙는다)
- **픽셀 유지** — `image-rendering: pixelated` + 정수 배율.
  현재 CSS 가 「모든 수치는 2px 격자」로 서 있다
- 모바일 세로 · 웹 — 초기 로딩 용량 예산이 곧 제약
- Canvas 2D 만 쓴다. WebGL · 셰이더 없음
- 계절 4종을 런타임에 생성해 캐시 중 — 그림 자산으로 바꾸면 4배가 된다
