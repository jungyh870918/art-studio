## 1. 왜 완성된 프레임이 아니라 부품인가

생성 AI에게 「9-slice로 늘릴 수 있는 프레임」을 시키면 거의 항상 가장자리 한가운데까지 장식을 넣는다.
그 자리는 늘어나는 자리라서 패널 크기가 바뀌면 그 문양만 뭉개진다.

그래서 **부품 3종만 받고 조립은 `npm run art:frame`이 한다.** 그러면 규칙이 지켜지지 않을 수가 없다.

```text
corner   모서리 장식 한 개  → 네 귀퉁이에 좌우·상하 반전해서 놓는다
edge-h   가로 띠 한 마디    → 위·아래 띠에 이어 붙인다 (아래는 상하 반전)
center   가운데 바탕        → 안쪽을 채운다 (늘어난다)
```

**세로 띠는 발주하지 않는다.** `panel`은 네 변의 slice가 96px로 같아서, 조립기가 가로 띠를 90° 돌려
그대로 쓴다. 비율이 어긋나지 않는다. (`banner`는 상하 64 · 좌우 96으로 달라서 그때는 세로 띠를 따로 받는다.)

---

## 2. 규격

최종 프레임은 512×512, 가장자리 폭 96px 균등이다. 부품은 **크게 받아 코드가 줄인다.**

| 부품 | 파일명 | 발주 크기 | 최종 배치 크기 | 비율 |
|---|---|---|---|---|
| 모서리 | `panel.corner.png` | 384×384 | 96×96 | 1:1 고정 |
| 가로 띠 한 마디 | `panel.edge-h.png` | 384×384 | 두께 96 · 안쪽 320에 3마디 | 1:1 고정 |
| 가운데 바탕 | `panel.center.png` | 640×640 | 320×320 | 1:1 고정 |

**비율이 틀리면 조립기가 늘려서 맞춘다.** 정사각으로 받는 것이 규격의 핵심이다.

- 배경: **크로마 초록 단색.** 투명 PNG로 받지 않는다 — 생성 AI의 「투명 배경」은 알파가 있어도
  전 픽셀이 불투명한 경우가 흔하다. `npm run art:cutout`이 초록을 지우고 알파·despill까지 한다
- 형식: PNG. 후보는 `panel.corner.a.png` `…b.png` 처럼 받아 두고, 채택본만 위 이름으로 확정한다
- 채택본 위치: `assets/_master/ui/` — 규격 검사에서 제외되는 자리다

## 3. 조립 구조가 강제하는 것 — 이 네 줄이 이번 발주의 핵심이다

**① 모서리는 반전되어 네 번 쓰인다.**
좌상단 것 하나만 그리고, 나머지 세 귀퉁이는 좌우·상하로 뒤집어 놓는다.
→ 글자, 문장(紋章), 한쪽으로 흐르는 장식은 넣지 않는다. 뒤집어도 성립하는 형태여야 한다.

**② 띠는 이어 붙는다.**
마디 하나의 **왼쪽 끝과 오른쪽 끝이 맞물려야** 한다. 끊긴 무늬가 반복되면 이음매가 그대로 드러난다.

**③ 아래쪽 띠는 상하로 뒤집혀 쓰인다.**
위아래가 다른 띠(예: 아래로만 늘어지는 술 장식)는 아래 변에서 거꾸로 매달린다.
→ 위아래 대칭이거나, 뒤집혀도 어색하지 않은 띠여야 한다.

**④ 가운데 바탕은 늘어난다.**
패널 크기에 따라 320×320이 아무 비율로나 늘어난다.
→ 방향성 있는 무늬·그라데이션·모서리 쪽으로 몰린 장식을 넣지 않는다. 평평한 아이보리에 미세한 종이/천 질감만.

그리고 공통으로 — **장식이 부품 밖으로 삐져나오면 조립할 때 잘린다.** 여백 안에 완전히 들어와야 한다.

## 4. 색

실측값이다. 프롬프트에 그대로 넣는다.

| 토큰 | 값 | 쓰이는 곳 |
|---|---|---|
| `panel.bg` | `#e4ddd8` | 바탕 아이보리 — **순백이 아니라 따뜻한 회색이다** |
| `gold.line` | `#d1c6b7` | 가는 금선. 테두리의 주된 선 |
| `gold.metal` | `#54402e` | 금속 금장. 모서리 장식의 깊은 부분 |

금장이 두 층이라는 것이 이번 색의 요점이다. 하나로 묶으면 둘 중 하나가 반드시 틀어진다.

## 5. 프롬프트

한 대화에서 세 부품을 이어서 뽑는다.
`ART_DIRECTION.md` §7의 「주문 하나 = 새 대화 하나」에 대한 **의도적 예외**다 —
세 부품은 서로 붙어야 하므로 같은 문맥에서 나오는 편이 낫다. 대신 매 생성마다 앵커를 다시 첨부한다.

### 5-1. 모서리

```text
[첨부: 11_44_21 (2)]

첨부한 게임 화면과 같은 화풍으로, UI 패널 프레임의 **왼쪽 위 모서리 장식 하나만** 그려라.

- 정사각 384×384, 배경은 순수한 초록 단색 (#00ff00)
- 밝은 아이보리 #e4ddd8 바탕에 가는 금선 #d1c6b7, 장식의 깊은 부분은 #54402e
- 판타지 왕국의 금세공. 얇고 정밀하게. 두껍고 무거운 금장이 아니다
- 장식은 캔버스 안에 완전히 들어올 것. 가장자리에 닿거나 잘리지 않게
- 좌우·상하로 뒤집어도 성립하는 형태. 글자·문장·한쪽으로 흐르는 곡선은 넣지 말 것
- 모서리 하나만. 프레임 전체나 패널을 그리지 말 것
- 그림자·원근·입체 조명 없이 정면에서 본 평면
```

### 5-2. 가로 띠 한 마디

```text
[첨부: 11_44_21 (2)]

같은 화풍·같은 금장으로, 위 모서리와 이어지는 **가로 테두리 띠의 한 마디**를 그려라.

- 정사각 384×384, 배경은 순수한 초록 단색 (#00ff00)
- 색은 앞과 같다: 바탕 #e4ddd8 · 가는 금선 #d1c6b7 · 깊은 금속 #54402e
- **왼쪽 끝과 오른쪽 끝의 무늬가 정확히 맞물릴 것.** 이 마디를 가로로 반복해 띠를 만든다
- **위아래 대칭.** 이 띠는 아래쪽 변에서 상하로 뒤집혀 쓰인다
- 반복해도 눈에 띄지 않을 잔잔한 문양. 큰 장식이나 중앙 강조를 넣지 말 것
- 띠 한 마디만. 프레임 전체를 그리지 말 것
```

### 5-3. 가운데 바탕

```text
[첨부: 11_44_21 (2)]

같은 화풍으로, 패널 안쪽을 채울 **바탕 질감**을 그려라.

- 정사각 640×640, 배경 없이 화면 전체가 바탕
- 밝은 아이보리 #e4ddd8 단색에 가까운 평면. 종이나 얇은 천의 미세한 질감만
- **완전히 균질할 것.** 이 그림은 임의의 비율로 늘어난다 —
  무늬·그라데이션·비네팅·중앙 강조·모서리 장식을 넣지 말 것
- 금선이나 테두리를 넣지 말 것. 테두리는 다른 부품이 맡는다
```

## 6. 몇 장 받고 어떻게 판정하는가

- **부품 세트 3벌**을 받는다. 한 벌만 받으면 고를 것이 없다
- 세 벌을 각각 `npm run art:frame`으로 조립한다 — 부품 상태로는 판정하지 않는다
- 조립한 프레임을 `npm run shot`으로 판 위에 올려 **실제 화면에서** 본다
- 판정 기준은 `../reviews/REVIEW_LOG_ivory-frame.md` Review 03에 기록한다

이번 판정에서 볼 것:

1. 이음매가 보이는가 (②③이 지켜졌는가 — 조립해 봐야 드러난다)
2. 모서리를 뒤집었을 때 어색하지 않은가 (①)
3. 아이보리가 콘셉트 아트와 같은 톤으로 읽히는가
4. 금선이 실제 표시 크기에서 사라지지 않는가 — **512px 원본에서 잘 보이던 가는 선이
   화면에서 죽는 것이 이 화풍의 가장 큰 위험이다**

규격 검사(`npm run art:check`)는 조립 뒤에 돌린다. **통과는 승인이 아니다** — 채택은 디렉터가 한다.
