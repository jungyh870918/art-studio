이 단계의 합격 조건은 **하나**였다 —
받은 배경을 게임에 넣고 찍었을 때 **왜곡 없이 · 오브젝트가 다 보이고 · 핫스폿이 그림 위 제자리에** 오는가.
[`../2026-08-17_background-integration/`](../2026-08-17_background-integration/) 시점에는 **셋 다 실패**했다.

| | 전 (가로 320×135) | 후 (세로 942×1305) |
|---|---|---|
| 왜곡 | 찌그러짐 또는 세로 압축 | **없음** — 늘리지 않고 채운 뒤 잘라낸다 |
| 오브젝트 | 잘라 쓰면 내용의 28%만 남음 | **전부 보인다** |
| 핫스폿 | 그림과 무관한 자리 | **일곱 개 다 제자리** |

## 2. 화면 치수 — D1을 1~2px 고쳤다

**D1 941×1672 → 942×1674 로 올렸다.** 이유는 미적인 것이 아니다.

기획서 §05가 화면을 세 층으로 가르고, 스튜디오 §1이 **「D1은 World 층만 지배한다」**고 확정했다.
그래서 UI는 자기 좌표계를 가질 수 있고, 실제로 그래야 했다 — **Galmuri가 도트 폰트**라
설계 크기의 정수 배가 아니면 글자가 뭉갠다. 941/3 = 313.67 이라 배율 3이 떨어지지 않았다.

```
942 = 314 × 3        1674 = 558 × 3
```

| 층 | 좌표계 | 값 |
|---|---|---|
| 화면 (World·핫스폿·마우스) | 뷰포트 | **942×1674** |
| UI (상단 바·패널·선택지·초상화) | 설계 픽셀 → 3배 확대 | **314×558** |

| 밴드 | 화면 px | 화면 비중 | 목업 |
|---|---|---|---|
| 상단 바 | 147 | 8.8% | 146 (8.7%) |
| **월드** | **1305** | **78.0%** | 78.6% |
| 하단 패널 | 222 | 13.3% | — |

**D1에서 벌어진 값은 가로 +1px · 세로 +2px (0.1%)다.** 되돌리려면 UI 배율을 버려야 한다.
스튜디오가 되돌리라면 되돌린다 — 지금은 승인 자산이 배경 1장뿐이라 비용이 거의 0이다.

## 3. 배경 규격이 정해졌다 — **1024×1418**

월드 밴드 942×1305 의 비율은 **1 : 1.385** 다.
받은 `01_bull_harbor` 는 1024×1536 (2:3, 1:1.5) 이라 **위아래로 59px씩 잘린다.**

늘리는 대신 잘라내기를 골랐다. 늘리면 가로로 8% 뚱뚱해진다 —
황소 동상과 인물 얼굴에서 바로 보인다. 아트 기준 §4 「넉넉히 그리고 화면이 세로로 잘라 쓴다」와도 맞는다.

> **다음 주문부터 1024×1418 로 받으면 잘림이 0이 된다.**
> 게임 저장소 `docs/art/PROMPT.md` 와 `ORDER_01`~`06` 여섯 장 전부 이 값으로 고쳤다.

잘라내는 위치는 장면마다 `"bg_anchor": [x, y]` 로 조절한다. 기본은 가운데(0.5).

## 4. 좌표를 정규화했다

핫스폿을 **0~1 비율**로 다시 썼다. 장면 JSON에 `"coord_space": "norm"` 한 줄이 선언이다.

- 옛 320×135 픽셀 좌표는 세로 밴드로 옮길 방법이 없다 — 가로 ×2.94 · 세로 ×9.67 로 배율이 3.3배 어긋난다
- 눈대중으로 찍지 않았다. **받은 그림에 64px 격자를 씌워 원본 픽셀로 읽고**,
  잘라내기 수식을 태워 비율로 환산했다
- 아직 옮기지 않은 장면 5개는 옛 좌표를 축마다 늘려 밴드를 채운다. 자리표시자와 핫스폿이
  같은 배율을 타므로 서로 어긋나지 않는다

## 5. 상단 바 — 코드가 그린다

목업 `01_explore` 를 재서 옮겼다. 배경과 같은 자리표시자 규칙이다 —
`assets/ui/topbar.png` 를 넣으면 코드 대신 그 그림을 쓴다.

| 목업 | 구현 |
|---|---|
| 왼쪽 햄버거 버튼 104×104 | ✅ 35×35 설계 px (=105 화면 px) |
| 가운데 「CH.1 황소항」 | ✅ 장소 이름은 장면 데이터에서 읽는다 |
| 오른쪽 수첩 버튼 + 배지 3 | ⚠ **수첩 대신 「대화 기록」을 걸었다** |

> 수첩은 화면도 데이터도 없다 (스튜디오 §0). **없는 문을 그려 두지 않는다.**
> 수첩이 생기면 이 자리를 내준다.

모서리는 §06 v2.2 개정대로 **곡선이 아니라 1~2 게임픽셀 계단형 깎기**다.

## 6. 아직 목업과 다른 것 — 배틀 화면

배틀 HUD가 상단 바에 깔려 있어 **가려지지 않게만** 내렸다. 목업 `03_battle` 의 배치
(월드 아래 3단 상태 카드 + 논거 카드 3장 + 하단 초상·목표·가방)는 **손대지 않았다.**

이유: 그 배치는 **논거 카드 일러스트 11장**을 전제한다 (`ASSET_MANIFEST` §7).
지금 만들면 빈 상자만 늘어선다. **일러스트가 나온 뒤에 한다.**

## 7. 스튜디오에게 필요한 것

| | | 급한가 |
|---|---|---|
| A | **D1 941×1672 → 942×1674 승인** (§2). 되돌리려면 UI 배율을 버려야 한다 | 지금 |
| B | **배경 규격 1024×1418 승인** (§3). 다음 주문부터 적용 | 다음 발주 전 |
| C | 배경을 **3~4장씩** 다시 받는 것 — 지금은 장면당 1장이라 고를 것이 없다 | 다음 발주 |
| D | 상단 바 오른쪽 버튼: 수첩이 생길 때까지 「대화 기록」으로 둔다 (§5) | 급하지 않다 |

**여전히 막혀 있는 것은 캐릭터다.** D3(제작 방식)이 안 정해졌고, 윤세라 외형도 대기 중이다.
셸이 올라갔으니 **이제 배경 위에 인물을 세운 화면을 보고 판단할 수 있다.**
