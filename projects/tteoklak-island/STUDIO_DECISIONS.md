# 스튜디오 잠정 결정 — REQUEST_TO_DIRECTOR 회신

작성 2026-08-17 · 스튜디오 → 게임 구현 세션
대상: [`REQUEST_TO_DIRECTOR.md`](REQUEST_TO_DIRECTOR.md) D1~D6

디렉터가 **「스튜디오 판단대로 진행」**을 지시했다.
따라서 아래는 **잠정 결정**이며, 전부 디렉터가 뒤집을 수 있다.
항목마다 **근거**와 **뒤집는 비용**을 적었다. 비용이 싼 지금 정하고 굴린다.

> **미적 판단은 여기서 하지 않는다.** D5와 §5의 새 질문 하나는
> 근거만 세우고 **디렉터 확인 표시**를 남겼다. (`CLAUDE.md` §3)

## 0. 먼저 — 「확인 불가」였던 것이 전부 풀렸다

`REQUEST`와 [`MOCKUP_UI_AUDIT`](brief/MOCKUP_UI_AUDIT.md)가 남겨 둔 미지수를
게임 저장소 `data/` 와 기획서에서 직접 확인했다. **추측이 아니라 읽은 값이다.**

| 질문 | 답 | 출처 |
|---|---|---|
| 명명 인물 5명인가 8명인가 | **5명** | `data/characters/` — han_gaemi · boss · sera · park · broker |
| 논거 카드 일러스트 몇 개인가 | **11** (3페이즈 × 3~4 선택지) · 모순 카드 4종 | `data/battles/prologue_battles.json` |
| 증거 썸네일 18종인가 | **시스템이 없다.** 수첩·증거가 데이터에도 코드에도 없다 | `data/` · `scripts/` 전수 검색 |
| 카페가 프롤로그 장면인가 | **아니다.** 장면은 6개뿐 | `data/scenes/` · 기획서 §01 |
| 배틀 클로즈업 배경이 필요한가 | **자리가 없다.** 배틀 데이터에 background 필드 자체가 없다 | 같은 파일 |
| 아이템 몇 개인가 | **12** ✅ 기존 목록 정확 | `data/items/` |
| 표정 목록을 대사에서 뽑을 수 있나 | **없다.** emotion/expression 필드가 존재하지 않는다 | `data/dialogues/` |
| 기획서 §06 라운드 규정 원문 | 금지 목록 「**20px 라운드**」 · 규격표 「**둥글리지 않는다. 반경 0**」 | 기획서 §06 |

### 0-1. 견적이 오히려 줄었다

[`MOCKUP_UI_AUDIT`](brief/MOCKUP_UI_AUDIT.md)가 "배틀이 수첩보다 클 수 있다"고 경고했는데,
실제로 세어 보니 **논거 11개**다. 129가 아니다.
그리고 **증거 썸네일 18종은 발주 대상이 아니다** — 목업의 「3 / 18」은 목업 생성기가 지어낸 숫자이고,
받쳐 주는 시스템이 게임에 없다.

> `REQUEST` §3-3의 **「수첩이 가장 나중」**은 맞다. 다만 이유가 다르다 —
> 자산이 많아서가 아니라 **화면도 데이터도 아직 없어서**다.

## 1. 기획서 §05가 이미 답한 것 — 내 앞 문서를 고친다

[`CANVAS_DERIVATION`](brief/CANVAS_DERIVATION.md) §1에서 **「D1은 사실 질문이 둘」**이라고 썼는데,
기획서 §05를 읽어 보니 **그 답이 이미 문서에 있었다.** 내 쪽 정정이다.

기획서 §05는 화면을 **세 층**으로 가른다.

| 층 | 해상도 | 무엇이 | D1에 걸리나 |
|---|---|---|---|
| **World** | 기준 캔버스 (미확정) | 배경 · 캐릭터 · 소품 · 이펙트 · 자막 | **걸린다** |
| **Interaction** | **기기 실제 해상도** | 상단 바 · 상황 라인 · 행동 메뉴 · 선택지 카드 · 가방 · 배틀 HUD | 안 걸린다 |
| **Meta** | **기기 실제 해상도** | 수첩 · 대화 기록 · 저장 · 설정 · 타이틀 | 안 걸린다 |

그리고 §05 머리에 경고가 붙어 있다 —
**「이 장의 전제가 §23으로 뒤집혔다. 세 층 구조는 유효하지만 월드 쪽 숫자는 기준 캔버스가 정해질 때까지 미확정.」**

**따라서:**

- **D1이 지배하는 것은 배경과 캐릭터뿐이다.** UI 아이콘·장식은 애초에 D1 종속이 아니다
- **초상화도 D1에 안 걸린다.** 대화 UI에 속하므로 Interaction 층이다.
  (§05가 「초상화 96×96이 세계 화면의 절반 이상을 덮는다」를 구 방식의 문제로 든다 — UI로 올린 이유가 그것이다)

> **`REQUEST` §5의 「D1만 정해지면 초상화를 오늘이라도 발주할 수 있다」는 한 단계 더 낫다 —
> 초상화는 D1을 기다릴 필요조차 없다.** 막고 있는 것은 다른 것이다 (§5).

## 2. D1 — 기준 캔버스

### 잠정 결정: **942×1674**

> **2026-08-17 개정 — 941×1672 → 942×1674 승인.**
> 게임 쪽이 Galmuri 도트 폰트의 정수 배율 때문에 1~2px을 올렸다 (`942 = 314×3` · `1674 = 558×3`).
> 941은 3으로 나눠떨어지지 않는다. **미적 변경이 아니라 UI 배율 요구다.**
> 변화가 ×1.0011이라 파생 규격표의 ±4px 판독 오차 안에 들어간다 — **표는 그대로 유효하다.**
> 판정 근거: [`reviews/2026-08-17_portrait-shell/STUDIO_VERDICT.md`](reviews/2026-08-17_portrait-shell/STUDIO_VERDICT.md) §2

아래는 941을 고른 최초 근거이며, 942로 바뀐 뒤에도 그대로 성립한다.

| | |
|---|---|
| **적용 범위** | **World 층만** — 배경 · 캐릭터. UI는 기기 해상도 (§1) |
| **근거 1** | 앵커와 생성물이 같은 좌표계가 된다. 대조 시트에서 1:1로 겹쳐 본다 |
| **근거 2** | 목업에서 UI 부품을 잘라 임시 자산으로 쓸 수 있다 — 셸 구현이 빨라진다 |
| **근거 3** | 승인 자산이 **0개**다. 나중에 1080으로 옮기는 비용이 지금 가장 싸다 |
| **근거 4** | 기획서 §05가 월드 숫자를 「기준 캔버스 대기」로 명시적으로 비워 뒀다. 큰 값을 지금 확정할 이유가 없다 |
| **뒤집는 비용** | **지금은 거의 0.** 배경 후보 2장을 리사이즈하면 끝난다 |
| **뒤집어야 할 시점** | 배경 6장이 승인되기 전. 그 뒤에는 전부 다시 재야 한다 |

1080×1920을 안 고른 이유는 **×1.148이 정수배가 아니어서**다.
목업을 앵커로 붙일 때마다 리샘플이 끼고, [`ART_DIRECTION`](brief/ART_DIRECTION.md) §2가 측정한
「업스케일 배수 1×, 픽셀 격자 없음」과 어긋난다. 회화체 자산에는 거의 무해하지만,
**정수배로 갈 거라면 941 → 1882(×2)가 1080보다 안전하다.**

파생 규격은 [`CANVAS_DERIVATION`](brief/CANVAS_DERIVATION.md) §3 「가」 열을 확정판으로 쓴다.

## 3. D2 — 세로 전환 범위

### 잠정 결정: **(a) 세로 전용. 배경은 한 벌만 그린다**

**이건 새로 내리는 결정이 아니라 이미 내려진 것의 확인이다.**

- 기획서 §01 — **「모바일 세로를 1급으로 지원한다」**
- 기획서 표지 — **「세로 화면 기준」**
- 기획서 §05 — 세 층 구조가 세로를 기본 레이아웃으로 규정
- 목업 4장 전부 세로
- [`PROJECT_BRIEF`](brief/PROJECT_BRIEF.md) §5가 이미 「결정됨」으로 기록

**가로는 버리지 않되 배경을 두 벌 그리지 않는다.**
기획서 §05가 데스크톱 처리법을 이미 적어 뒀다 —
**「여백을 UI 배경색으로 칠하고 1px 테두리를 둘러 화면 속 화면으로 보이게 한다.
레터박스는 사고처럼 보이지만, 테두리 두른 스테이지는 의도처럼 보인다.」**
세로 스테이지를 가로 창 안에 두면 되고, **배경 발주에는 영향이 없다.**

| | |
|---|---|
| **아트 발주에 미치는 영향** | **없다.** 배경 6장 그대로 |
| **구현에 미치는 영향** | 기존 6장면 좌표 재배치 · Modern 셸 구현 (게임 쪽 일) |
| **뒤집는 비용** | 아트 쪽은 0. 구현 쪽은 셸 착수 전이면 0 |

> `REQUEST` §D2가 「내가 고르지 않는다」고 넘긴 것은 신중했지만,
> **정본 네 곳이 이미 같은 답을 적고 있었다.** 디렉터에게 다시 물을 사안이 아니다.

## 5. D5 — 화풍 밀도 · ⚠ 디렉터 확인 필요

### 잠정 결정: **회화체로 통일. 다만 이건 내가 정할 것이 아니다**

| 근거 | |
|---|---|
| 측정 | [`ART_DIRECTION`](brief/ART_DIRECTION.md) §2 — 목업 4장 전부 업스케일 1×, 픽셀 격자 없음, 고유색 14만~24만. **도트가 아니다** |
| 화면 내 모순 | 04 수첩 한 화면 안에 **회화체 반신(P3)과 도트 흉상(P4)이 공존**한다. 일관된 의도로 읽기 어렵다 |
| 다른 잡음 | 같은 화면에서 **인물 이름이 틀렸다** (§6). 목업 생성 과정에 흔들림이 있다는 증거 |
| 판정 | 도트 흉상은 **의도가 아니라 생성 잡음**일 가능성이 높다 |

> **⚠ 여기가 이 문서에서 가장 약한 결정이다.**
> 「같은 게임 안에서 자산 종류마다 밀도를 달리한다」는 것은 충분히 있을 수 있는 아트 방향이고,
> 실제로 수첩은 «종이에 붙인 것»이라는 은유가 있어서 **의도적으로 거칠게 갈 이유도 있다.**
> 디렉터가 04 화면의 두 흉상을 나란히 보고 한 번 판정해 주면 좋겠다.
> **뒤집는 비용: 지금은 0** (해당 자산 미착수). 수첩 발주 시작 후에는 비싸진다.

## 6. 윤세라의 외형 — **결정됨 (2026-08-17)**

> ### ✅ 디렉터 결정 — **목업이 정본이다.**
>
> 초상화 보류가 풀렸다. **5명 15표정 전부 발주한다** ([`brief/ORDER_PORTRAITS.md`](brief/ORDER_PORTRAITS.md)).
>
> **다만 목업이 이긴 범위는 외형뿐이다.** 이름 표기(「윤세라」)와 인물 배정은 데이터가 맞다 —
> 목업 03·04가 broker에게 세라 명패를 붙인 것은 생성 잡음이고 채택하지 않는다.
>
> 게임 쪽 반영 필요: `data/characters` 의 sera 색·머리 모양, 「장식을 더하지 않는다」 주석 폐기,
> 기획서 §6.7. 상세는 `ORDER_PORTRAITS` §6-2.

아래는 결정 전에 정리한 근거다. 기록으로 남긴다.

### (당시) 새 질문 — 윤세라의 외형이 목업과 데이터에서 다르다

**`REQUEST`에 없던 것이고, 초상화 발주를 실제로 막는 것이다.**

| 출처 | 윤세라 |
|---|---|
| `data/characters/prologue_characters.json` | **적갈색 단발(bob) · 검은 터틀넥 · 긴 코트 · 각진 실루엣**<br>초상화 주석: 「감정이 적어 보이지만 눈썹과 시선으로 표현. **장식을 더하지 않는 것이 이 인물의 디자인이다**」 |
| 기획서 표지 | 차트 분석가 · **허리의 금속 자** · 감정어를 안 씀 |
| **목업 01 · 02** | **긴 갈색 웨이브 · 보라색 정장 · 금 목걸이 · 큰 귀걸이 · 부드러운 인상** |

**거의 반대 방향이다.** 그리고 목업 03·04는 선글라스 쓴 남자(broker)의 명패에
**「운세라」**라고 적어 놨다 — 이름 표기도, 인물 배정도 틀렸다.

기획서 §23은 **「문서가 그림과 다르면 문서가 틀린 것」**이라고 한다.
하지만 이 규칙은 §23의 문맥상 **화풍**에 대한 것이고,
이걸 인물 디자인까지 확장하면 **의도적으로 설계된 캐릭터(「장식을 더하지 않는다」)를
그 반대로 덮어쓰게 된다.**

> **⚠ 디렉터 결정 필요 — 윤세라는 어느 쪽인가.**
> (a) 목업이 이긴다 → `data/characters` 와 기획서 §6.7을 고친다
> (b) 데이터가 이긴다 → 목업의 윤세라는 생성 잡음. 초상화를 데이터대로 발주한다
> (c) 절충
>
> **초상화 5명 중 1명이 여기 걸려 있다.** 나머지 4명은 이 답 없이 진행 가능하다.

## 7. D6 — 후보 장수

### 잠정 결정: 아래 표대로

`REQUEST` §D6이 「근거는 내가 정한 것뿐」이라고 했다. 근거를 붙인다 —
**병목은 생성 왕복이다** ([`QUESTIONS_TO_STUDIO`](QUESTIONS_TO_STUDIO.md) §1).
따라서 **고르는 값이 큰 것에만 장수를 쓴다.**

| 자산 | 후보 | 근거 |
|---|---|---|
| **배경** | **4** | 화면의 50~78%. 시간대·카메라·밀도가 갈린다. 한 장으로는 못 고른다 (실제로 겪음) |
| **인물 반신 (P1·P2·P3)** | **4** | 얼굴 정체성이 한 번 정해지면 되돌리기 비싸다 |
| **캐릭터 스프라이트** | — | D3 미결. 착수 안 함 |
| **아이콘 · 장식** | **2** · **시트로 한 번에** | 개별 왕복이 아깝다. 한 대화에서 여러 개를 한 장에 받아 고른다 |
| **논거 카드 일러스트 11** | **2** · 시트 | 위와 같음 |

> **아이콘·장식은 「주문 하나 = 새 대화 하나」(R4)를 시트 단위로 읽는다.**
> 부품 20종을 20번 왕복하면 그것만으로 병목이 된다.
> R4의 취지는 «맥락 오염 방지»이므로, **같은 종류를 한 시트로 받는 것은 취지에 어긋나지 않는다.**
> 이 해석이 틀리면 알려 주면 되돌린다.

## 8. 발주 순서 — 확정판

`REQUEST` §5를 위 결정에 맞춰 다시 짠다.

```
지금 ─┬─ 배경 6장 (후보 4장씩)          D1 확정됨 · D2 영향 없음
      └─ 초상화 4명 (한개미·부장·박프로·환전소남)
                                        D1 무관 (UI 층)
         └ 윤세라는 §6 답을 기다린다

다음 ── 세로 셸 구현 (게임 쪽)          배경을 화면에 올린다
   │
   ├─ 배경 올라간 화면 촬영 → 캐릭터 크기 실측
   │
   ├─ D3 · D4 결정 → 캐릭터 5명
   └─ UI 아이콘 · 장식 (시트 단위)

나중 ── 수첩                            화면도 데이터도 없다. 시스템부터
```

**바뀐 것 둘:**
1. **배경과 초상화를 동시에 시작한다.** 초상화가 D1을 안 기다린다는 게 §1에서 나왔다
2. **초상화는 4명 먼저.** 윤세라 한 명 때문에 넷을 세우지 않는다

## 9. 게임 쪽에 돌려주는 것

`REQUEST`가 「내 숙제」로 남긴 것 중 **하나는 불가능하고 하나는 우리가 했다.**

| 항목 | 결과 |
|---|---|
| **표정 목록 추출** | **불가능하다.** `data/dialogues/` 에 emotion·expression 필드가 없다.<br>나온 것은 화자별 대사량뿐 — player 59 · broker 42 · sera 40 · boss 21 · park 14.<br>**표정 세트는 추출이 아니라 설계다.** 아트 결정이므로 스튜디오가 안을 만들어 올린다 |
| **UI 부품 목록** | 우리가 만들었다 — [`MOCKUP_UI_AUDIT`](brief/MOCKUP_UI_AUDIT.md) 31종 |
| **파생 규격표** | 우리가 만들었다 — [`CANVAS_DERIVATION`](brief/CANVAS_DERIVATION.md) |

### 기획서 §06 개정 제안 (게임 쪽 문서라 우리가 고치지 않는다)

원문을 확인했다. 금지 목록은 **「20px 라운드」**, 규격표는 **「둥글리지 않는다. 반경 0」**이다.
목업을 4배로 확대해 보면 곡선이 아니라 **4~6px짜리 계단형 깎기(chamfer)**다.

> **목업은 「20px 라운드」 금지를 어기지 않는다.** 어긋나는 것은 「반경 0」 한 줄뿐이고,
> 그나마 라운드가 아니라 «깎기»다.
>
> 제안 문구 — **「반경 0. 다만 모서리 1~2 게임픽셀 계단형 깎기는 허용한다.」**
> `REQUEST` §3-2가 제안한 「작은 반경 허용」보다 이쪽이 목업에 정확하다.

## 10. 이 문서의 상태

**전부 잠정이다.** 디렉터가 한 줄로 뒤집을 수 있고, 지금은 뒤집는 비용이 거의 0이다.

**디렉터 확인이 있으면 좋은 것 둘** — 나머지는 확인 없이 굴려도 된다.

| | 무엇 | 언제까지 |
|---|---|---|
| ⚠ **A** | **§6 윤세라 외형** — 목업인가 데이터인가 | 초상화 5명째 발주 전 |
| ⚠ **B** | **§5 D5 밀도** — 수첩 흉상을 도트로 둘 것인가 | 수첩 착수 전 (한참 뒤) |

**A만 지금 걸린다.** B는 시간이 있다.
