## 1. 규격

```
경로   assets/sprites/portraits/<character_id>.png
발주   252 × 252  (마스터. 63 설계px × 4)
전달   189 × 189  (게임에 넣는 값. 63 설계px × 3)
배경   불투명. 인물별 backdrop 색으로 채운다 (§4)
```

> **2026-08-17 정정 — 188이 아니라 189다.**
> 게임 쪽 슬롯이 `PORTRAIT_SIZE = 63 설계px × UI 배율 3 = 189`이고,
> **목업 실측 189×189와 정확히 일치한다.** 188은 내가 4의 배수로 반올림한 값이었다 —
> 그 관행이 여기서는 틀렸다. UI 층은 4가 아니라 **설계 픽셀 정수**에 맞춰야 한다
> ([`CANVAS_DERIVATION.md`](CANVAS_DERIVATION.md) §3-0).

**발주는 252, 전달은 189로 갈라 둔다.** 이유는 배경과 같다 —
**크게 받아 줄인다** (`ART_DIRECTION` §4). UI 배율이 나중에 ×4로 올라가는 기기가 있으면
189짜리는 확대돼 뭉개지지만, 252 마스터가 있으면 그대로 내보내면 된다.
축소는 안전하고 확대는 아니다. 생성 비용 차이는 없다.

- **현재 코드의 96×96은 폐기 규격이다.** 목업 실측 189×189
- **D1(기준 캔버스)에 걸리지 않는다.** 기획서 §05상 Interaction 층 = 기기 해상도.
  188은 「목업 좌표계에서 이 크기로 보인다」는 기준값이고, 표시는 정수 배율로 확대된다
- 잘림 범위: **가슴 위**. 목업 02의 윤세라 초상과 같은 구도
- **알파 없음.** 목업 초상은 프레임 안이 색으로 차 있다

## 2. 표정 세트 — 대사에서 설계했다

`REQUEST` §2-2가 「대사 데이터에서 뽑겠다」고 했으나 **emotion·expression 필드가 없다.**
추출이 아니라 설계이므로, **실제 대사를 근거로** 최소 세트를 짰다.
근거 문장을 함께 적는다 — 늘리거나 줄일 때 판단할 수 있게.

## 3. 후보 장수

**표정당 4장** (`STUDIO_DECISIONS` §7 — 인물 반신 4).
얼굴 정체성이 한 번 정해지면 되돌리기 비싸다.

다만 **표정마다 4장씩 새로 받지 않는다.**

```
1단계  인물당 «기본 표정» 4장  →  디렉터가 얼굴을 고른다   (4명 × 4 = 16장)
2단계  고른 얼굴을 앵커로 «나머지 표정» 2장씩             (8표정 × 2 = 16장)
```

**얼굴 정체성을 먼저 못 박고 표정을 파생시킨다.** 표정마다 독립으로 4장을 받으면
같은 인물로 안 보이는 문제가 그대로 재발한다 ([`PRODUCTION_STRATEGY`](../PRODUCTION_STRATEGY.md) §5 —
「얼굴 정체성은 고정」).

## 6. 윤세라 — 결정됨 (2026-08-17)

**디렉터 결정 — 외형은 «목업»이다.**

| | |
|---|---|
| ✅ **채택** | 목업 01·02 — 긴 갈색 웨이브 · 보라색 정장 · 금 목걸이 · 큰 귀걸이 |
| ❌ 폐기 | `data/characters` — 적갈색 단발 · 검은 터틀넥 · 긴 코트 · 「장식을 더하지 않는다」 |

**앵커는 `references/02_dialogue.png` 의 초상**이다. 목업 안에 이미 초상 형태로 들어 있어
따로 해석할 필요가 없다 — 그 그림을 그대로 기준으로 삼는다.

### 6-1. 목업이 이긴 범위 — 외형뿐이다

혼동이 생길 자리라 못 박아 둔다.

| | 정본 |
|---|---|
| **외형** (머리·의상·장신구·인상) | **목업** ✅ |
| **말투와 성격** | **대사 데이터** — 40줄은 그대로다. 감정어를 쓰지 않는다 |
| **이름 표기** | **「윤세라」** — 목업 03·04의 「운세라」는 **오기다** |
| **인물 배정** | 목업 03·04가 **선글라스 쓴 남자(broker)에게 세라 명패**를 붙여 놨다. **채택하지 않는다** |

> 목업 03·04의 이름 오기와 인물 배정 오류는 **생성 잡음**이다.
> 「그림이 이긴다」를 여기까지 밀면 배틀 상대와 파트너가 뒤바뀐다.

### 6-2. 그래서 생기는 일 — 게임 쪽 반영 필요

외형이 바뀌었으므로 **자리표시자 색과 문서가 어긋난다.** 우리가 고치지 않는다 (`CLAUDE.md` §9).

| 대상 | 지금 값 | 필요한 일 |
|---|---|---|
| `data/characters/prologue_characters.json` · `sera` | `hair #6b3226` 적갈 · `shirt #1b1820` 검정 · `hair_style: bob` · `has_coat` | 목업 기준으로 갱신 |
| 같은 파일 `portrait._note` | 「장식을 더하지 않는 것이 이 인물의 디자인이다」 | **이 문장이 폐기됐다** |
| 기획서 §6.7 · 표지 | 「각진 실루엣」 · 「허리의 금속 자」 | 「금속 자」를 남길지 확인 필요 |

**「금속 자」는 우리가 판단하지 않는다.** 소품이라 목업에서 안 보일 뿐일 수도 있다.

### 6-3. 표정은 그대로 3종

외형이 부드러워졌다고 표정을 늘리지 않는다. 근거는 §2-5.
**대사가 바뀌지 않았기 때문이다** — 「아니요. 미련 보존이에요.」 같은 말투는 그대로다.
